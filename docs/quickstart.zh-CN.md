# 快速开始

本指南走完从安装插件到完成一个带 TaskRun 证据的 AI Project 的最短可用路径。

## 前置条件

- 已安装 README 兼容性说明中的 DeepSeek Harness、Cordis、Node.js、Git 和 pnpm。
- Harness Profile 中已经配置可用的模型 Provider。Provider 凭据应保存在 Harness 配置中，不要写入 Project 需求或代码仓库。
- 一个允许 Agent 修改的本地代码仓库。第一次使用建议选择临时仓库或干净分支。
- 仓库已有可非交互执行的验证命令，例如 `pnpm test`、`npm test`，或 manifest 中记录的其他命令。

## 1. 安装并启用插件

按照 [安装](../README.zh-CN.md#安装) 完成安装，重启现有的 `dsh web` 进程并刷新当前页面，然后验证 Host：

```bash
curl --fail http://127.0.0.1:3080/project-orchestrator/api/health
```

成功响应为 `{"ok":true}`。从 Harness 侧边栏底部打开 **Project Orchestrator** 入口。

## 2. 创建智能体

1. 打开 **智能体**，选择 **创建智能体**。
2. 第一次使用建议选择手动配置，行为更容易复核。
3. 填写名称和执行指令，然后选择 Harness 中已配置的 Provider 与模型。
4. 只有在信任目标仓库时才使用 **完整工具**。只读智能体可以规划和审查，但不能实施修改。
5. **Runtime** 保持为 **本机默认环境**，最大并发设置为 `1`。
6. 创建智能体。

普通单 Host 流程直接使用本机默认环境即可。只有需要指定 Agent CLI、工作区根目录或单独维护执行配置时，才需要创建自定义 Runtime。

## 3. 创建 AI 项目

1. 打开 **项目**，选择 **新建项目**。
2. 选择 **AI 智能拆解** 和 **本地代码仓库**。
3. 选择已有的仓库目录。
4. 填写边界清晰、结果可观察的交付简报，并写明仓库已有的验证命令。例如：

```text
在当前仓库完成一个小型、可回滚的文档或代码修改。
只使用仓库 manifest 中已经确认存在的命令。
至少生成一个代码任务和一个独立的测试任务。
最终验证必须使用仓库已有的非交互测试命令。
```

5. 创建 Project，等待规划进入 **待批准**。

规划阶段只读检查仓库。如果 Planner 报告缺少仓库证据或无法确认验证命令，应先补齐仓库前置条件并重新规划，不要批准臆造的命令。

## 4. 添加并分配智能体

1. 打开 Project 的 **智能体**标签。
2. 选择 **添加智能体**，选择刚创建的 Agent，填写项目职责；适合时可以开启 **允许 AI 自动匹配**。
3. 打开 **任务**标签。
4. 逐项检查任务、依赖关系、验收标准和测试命令。
5. 如果仍有未分配任务，使用 **批量分配未分配任务**。

批准要求至少包含一个代码任务、一个测试任务；每个任务都必须绑定具备项目资格的智能体，并且每个任务都有非空验证命令。

## 5. 批准并执行

回到 **概览**，选择 **批准计划并开始实施**。确认前逐项检查 Shell 命令，因为批准的验证命令会在本机执行。

Project 会依次经过排队、Agent 执行和测试验证。遇到权限、Runtime、重试或其他需要人工处理的事项时，打开 **Inbox**。

## 6. 检查结果

打开 Project 的 **运行与证据**标签，确认：

- Project 和 Run 已进入 `completed`；
- 每个 TaskRun 已进入 `completed`；
- 记录的工作区是预期的仓库目录或 worktree；
- 每项验证结果的 exit code 都是 `0`；
- Agent 摘要、Transcript 和生成的 Artifact 与仓库实际变更一致。

最后自行检查 `git status` 和仓库 diff，再决定是否保留或提交 Agent 的修改。插件不会替你推送分支或创建 Pull Request。

## 常见阻塞

- **看不到入口：**检查 Loader Patch，重启现有 Web 进程，刷新页面，并调用 health 地址。
- **计划不能批准：**添加 active 项目智能体、为每个任务分配执行者，并确认计划包含代码任务、测试任务和验证命令。
- **Runtime 不可用：**改用本机默认环境，或将绑定的自定义 Runtime 恢复为在线状态。
- **Planner 被阻塞：**确认目录存在，并确认仓库公开了可非交互执行的验证命令。
- **执行需要决定：**打开 Inbox，检查上下文记录，再明确批准、拒绝、暂缓或重试。
